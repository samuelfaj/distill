# xai-grok-test-support

Shared test infrastructure for the Remote-Code crates. It provides a mock inference server, a mock OTLP server, a mock managed config server, SSE wire format generators, ACP stdio clients, a headless runner, and the `TestSandbox` and `TestProcess` owners for filesystem, environment, and subprocess lifecycle. It is consumed by `xai-grok-shell` integration tests, `xai-grok-pager-pty-harness` (`ContentController`), `xai-grok-sampler` tests, and `xai-grok-telemetry` tests.

> **Freshness rule:** update this README in the same PR that changes `src/`. Treat a `src/` diff without a README diff as incomplete.

How to test discovery lives with the `xai-grok-pager-pty-harness` crate. This file is the API reference for the shared test support surface.

## Module map

| Module | What it provides |
|--------|------------------|
| `acp_client` | `GrokStdioClient` drives `grok agent stdio` over real pipes. Spawn it with `spawn`, `spawn_with_sandbox`, or `spawn_with_options(server, cwd, SpawnOptions)`. Every spawn must run inside a tokio `LocalSet`, because the connection is not `Send`; wrap the test body with `run_in_local_set`. Requests run under a scaled budget and panic with the agent's stderr on timeout. `initialize`, `create_session`, `load_session`, and `cancel` panic on a protocol error; `prompt`, `set_model`, `set_mode`, and `ext_method` return `acp::Result` so a test can assert an error. Read what the agent sent with `transcript()` and `wait_for_transcript_entry`. `sandbox()` borrows the live sandbox and `into_sandbox()` kills the child and returns it. |
| `acp_agent_connection` | Crate private `AgentConnection`, the typed connection `GrokStdioClient` and `LeaderStdioClient` hold to their child. It owns every task it spawns, so dropping it stops the pipe reader, the writer, and any handler still waiting on a hold. Each request shape exists here once, untimed, returning `acp::Result`; the client adds the budget with the private `timed` and `timed_ok`. |
| `acp_agent_process` | Crate private process half shared by `GrokStdioClient` and `AcpTestClient`. `AgentProcessOptions::new(sandbox)` holds the sandbox; `spawn(server, cwd)` points it at the mock server, starts `grok agent stdio` through `TestProcess`, and returns the `#[must_use]` `SpawnedAgent { process, sandbox }`, so the sandbox drops after the child. |
| `acp_test_client` | `AcpTestClient` sends wire shapes the typed client cannot produce, such as escaped slash methods and string UUID ids. `send_line` writes one verbatim JSON-RPC line; `response_for_id` reads until the response with the same id, skipping notifications and auto refusing agent to client requests. |
| `acp_policy` | The scripted answers a test declares as data. `PermissionDecision` and `QuestionDecision` select the offered option of their kind or answer `cancelled` when no such option is offered. `HoldUntilCancel` leaves a request open until the session is next cancelled. `RequestPolicy::with_nth(n, decision)` answers request `n` (counted from 1 per kind) differently. `Interactivity` is how the client advertises itself: the default `Headless` keeps `nonInteractive: true` so the agent auto-cancels reverse interactions, while `Interactive { elicitation }` opts in and scripts the `x.ai/mcp/elicit` answer via `ElicitationDecision`. `ClientPolicy { permissions, questions, interactivity }` is what `SpawnOptions::with_policy` takes; its default allows every permission, dismisses every question, and stays headless. |
| `acp_ask_user_question` | Crate private mirror of the shell's `x.ai/ask_user_question` extension. It reads only the fields the client needs, fails a malformed request as invalid params, and builds the accepted and cancelled replies. This crate does not depend on `xai-grok-tools`, so a shell wire change touches only this module. |
| `acp_scripted_client` | Crate private `ScriptedClient`, the connection side of both stdio clients. It numbers each kind of agent request in arrival order, applies the `ClientPolicy` decision, holds an `AfterCancel` reply until its session is released, and records every message into the `Transcript`. `LeaderStdioClient` uses the default policy, so the crate has one permission policy. |
| `acp_hold_registry` | Crate private `HoldRegistry` behind `HoldUntilCancel`. `hold_until_released(session_id)` returns a guard that keeps the entry until dropped; `release_held_requests(session_id)` releases the requests held at that moment; `wait_for_held_request(session_id)` resolves once a request for the session is held. |
| `acp_transcript` | `TranscriptEntry` is the typed record of everything the agent sent, with the reply given for each round trip. Extension params are `serde_json::Value`. A round trip is recorded once answered, so a held request appears when `cancel` releases it. `wait_until(is_done)` is the one wait primitive; it sees the whole entry slice after each new entry. |
| `inference_override` | Response precedence shared by all inference routes, tried in this order: a named expectation matching endpoint and kind (`InferenceRequestMatcher`, `InferenceExpectation`), the endpoint's compatibility FIFO, auth rejection, the request's conversation script, then the concurrency cap. The module is crate private; only `InferenceRequestMatcher` and `InferenceExpectation` are public. |
| `inference_route` | Crate private `InferenceRoute`, the one handler behind `/v1/chat/completions`, `/v1/responses`, and `/v1/messages`. It builds the `InferenceRequest`, logs it, offers it to `inference_override`, and otherwise answers with the next queued agent turn or the response mode. The agent turn queue, the response mode, the Messages stop reason, and the chunk delay live here behind the `MockInferenceServer` setters. |
| `request_log` | `LogEntry` (public as `mock_server::LogEntry`) and the crate private `RequestLog`. Every route records an entry, the count stays exact after a test stops retaining entries, and the oldest entry is evicted past 1024. An inference entry carries `observed_failure: Option<ObservedFailure>`, what the mock decided on its own to do to the request: its conversation script's failure, the required auth 401, or the concurrency cap's 429; `None` for a plain answer and for a response the test enqueued. It is noted before any hold, so the log has it while a stall lasts. A `LogEntry` reads its inference body in all three request formats through `first_system_prompt()`, `offered_tool_names()`, and `tool_results()`; each is empty for an entry without a body. |
| `mock_server` | `MockInferenceServer` serves `/v1/chat/completions`, `/v1/responses`, `/v1/messages`, `/v1/models`, `/v1/settings`, and `/v1/user` on `127.0.0.1:0`, over plain HTTP or, with `start_tls`, over HTTPS. Model entries are `MockModelEntry` (`new`, `with_agent_type`, and chainable `with_*` setters), emitted top level as `parse_remote_model_value` reads them. Register a uniquely named response with `expect_response` or `expect_response_blocked`; duplicate names fail at registration and a request atomically claims one matching expectation. Overlapping duplicate requests replay by their `RepostIdentity` (endpoint, kind, `x-grok-req-id`, and a hash of the body). The returned `InferenceExpectation` exposes `wait_received`, `wait_blocked`, `wait_claims(n)`, `release`, `wait_satisfied`, `is_satisfied`, and `assert_satisfied`; `release` only opens the barrier, and satisfaction publishes once the primary crosses terminal and every overlapping copy settles. Echo mode streams `Echo: <last user message>`; `set_response(text)` reconstructs bytes exactly. Constructors `start`, `start_with_models`, `start_with_required_auth`, and `start_tls` return `anyhow::Result`; `start_tls` serves the default model with no required auth over HTTPS with a throwaway CA and no plaintext listener, so a request it logs implies a completed TLS handshake. `ca_pem_path()` is the path to the CA PEM a client must trust, `None` for a plain server. Settings are 404 until set. `/v1/user` serves a `UserInfo` whose tier `set_user_subscription_tier` controls. The request log is read through `requests()`, `request_bodies()`, `request_count()`, `has_chat_completion_request()`, `has_responses_request()`, `messages_request_count()`, `last_system_prompt()`, and `request_log_summary()`. It also serves storage (`POST /v1/storage`), feedback (`POST /v1/feedback`), telemetry (`POST /v1/events`), session writeback (`POST /sessions/{id}/data`, `PUT /sessions/{id}`), and privacy (`PUT /v1/privacy/coding-data-retention`), each read back through its accessor. The privacy PUT echoes the request flag with a 200 unless a response is queued for its path with `enqueue_response`, which lets a test refuse the write (for example a 400 policy denial); an empty queue keeps the echo. `url()` and `origin()` carry the scheme of the transport; `origin()` is the host without the `/v1` prefix. Runtime knobs include `set_models`, `set_messages_stop_reason`, `set_inference_concurrency_cap`, and `set_startup_fetch_delay` / `clear_startup_fetch_stall`. The server shuts down on drop. `GatedUploadProxy` is public here. |
| `mock_server_tls` | Crate private HTTPS transport behind `MockInferenceServer::start_tls`. `serve_tls(router, shutdown_rx)` generates a throwaway CA and a leaf for `127.0.0.1` and `localhost` with `rcgen`, binds `127.0.0.1:0`, and serves the router through `axum-server` with a `rustls::ServerConfig` built on an explicit provider (both `ring` and `aws-lc-rs` are linked into test binaries, so the default builder would panic). It returns the address and a `ThrowawayCa`, whose `pem_path()` names the CA PEM inside a `TempDir` kept alive with the server. The serve task `select!`s the server's shutdown oneshot and calls `Handle::shutdown`, so both transports stop on the same `Drop` trigger; TLS cuts in-flight connections where plain drains them. |
| `gated_upload_proxy` | `GatedUploadProxy::start(upstream_url)` stands in for the trace upload endpoint. It holds every request until `open()`, then forwards it to the upstream mock over a raw one shot HTTP/1.1 round trip with no HTTP client dependency. Point `GROK_TRACE_UPLOAD_URL` at its `url()` so "uploads still pending" is an ordering fact rather than a timing one. |
| `storage_endpoint` | `StorageUpload` (public as `mock_server::StorageUpload`) and the crate private `StorageEndpointState` behind `POST /v1/storage`. Every attempt is counted, every attempt while the 401 gate is closed is rejected, and an accepted upload is recorded with its `X-Storage-Path`, size, body up to 256 KiB, and raw `Authorization` header. |
| `tools` | `Tool`, exported at the crate root, names what a scripted call invokes. Most variants are built in tools, each carrying the name GrokBuild offers (for example `Read` is `read_file`, `EnterPlanMode` is `enter_plan_mode`, `WebSearch` is `web_search`, `Question` is `ask_user_question`, `Todo` is `todo_write`, `SchedulerCreate` is `scheduler_create`, `Workflow` is `workflow`). `TaskCreate`, `TaskUpdate`, and `CronCreate` are the vocabulary the conformance cases use and become one `todo_write` or `scheduler_create` call. `Mcp { server, tool }`, built by `Tool::mcp`, is a tool on an MCP server, offered as `server__tool` with the call's arguments passed through, or through the `use_tool` meta tool as `{ tool_name, tool_input }` when tool search offers that in its place. `Tool::pick` writes the case's arguments in GrokBuild's shape, filling the required fields a case may leave out (a `run_terminal_command` description from the command, a `todo_write` status of pending), then resolves the result against the tools a request offers. `Tool` is `Clone` but not `Copy`. |
| `conversation` | `ReadConversation`, exported at the crate root, is a conversation as the mock saw it, read through `MockInferenceServer::conversation(n)`, `conversation_for_system_prompt(contains)`, or `conversations()`. It exposes `number()`, `requests()`, `first_system_prompt()`, `last_reply()`, `saw_tool_call(Tool)`, and `tool_result(call_id)`; the reply that ended the conversation is in no request. The crate private `ConversationId` and `ConversationKey` group foreground requests: requests with the same key are one conversation, numbered in the order the mock first saw each, so a parent and its subagent child stay apart. The key is the `x-grok-session-id` header, else the first system message, else unkeyed. Auxiliary requests take no number. |
| `inference_request` | `InferenceEndpoint` (public at the crate root and from `mock_server`), the crate private `InferenceRequest`, and crate private readers over a request body in all three formats. `InferenceRequest::new` classifies the request on arrival: a non empty `x-grok-turn-idx` makes it foreground, else a non empty `x-grok-req-id` makes it auxiliary, else two or more offered tools make it foreground. A foreground request takes its conversation number, so auxiliary queries never shift a number a script names. The readers give the model named, the system and user messages, the tool calls the agent carried back, the offered tools, and the tool results, each across all three formats. |
| `conversation_script` | What a test scripts for the model, exported at the crate root as `Conversation`, `MockToolCall`, `ScriptViolation`, and `mock_call_id`. `Conversation::nth(n)` scripts the conversation with that number; `Conversation::for_system_prompt(contains)` scripts the first conversation no `nth` names whose first system prompt contains the text. Build it a turn at a time: `.calls([MockToolCall, ..])` adds a turn's tool calls and `.reply(text)` closes the turn, so every conversation must end with a `.reply`. A `MockToolCall::new(tool, arguments)` may pin the result the next request carries for it with `.result_contains(text)` or `.result_matches(pattern)`. A turn's setters, applied before its closing `.reply`: `.at_request(nth)` pins the turn to the nth request of the conversation, counted from 1 over every request that reaches the script, instead of the turn after the one before it; a pinned turn is outside the turn order, so the unpinned turns are served in list order as if it were not listed. `.stall(Duration)` holds the turn's answer, a failure's included, before its first byte. The failure setters answer their count of requests in place of the content, in the order declared, and never advance the script, so a retry meets the same position: `.refuse(StatusFailure)` refuses with an HTTP status, a `Retry-After`, and a custom or default JSON body; `.cut(count)` answers with `CUT_REPLY` stopped at the output token limit; `.fail_stream(StreamError)` fails the stream with one error event; `.doom_loop(count)` answers with the turn's first tool call again under a fresh call id, or with `LOOPING_REPLY` when the turn has no calls; `.drop_connection(count)` closes the connection before the response head. Call ids are `mock_call_id(conversation, n)`, so only this conversation's results advance its script. `at_request(0)`, `StatusFailure::new` outside 100 to 999, and two turns of one script pinned to the same request all panic. A `ScriptViolation` is recorded rather than failing the request. |
| `conversation_replay` | The crate private `ConversationReplay` plays each script forward one request at a time. `respond(&InferenceRequest)` returns the `ServedReply` for a request (the `ModelReply`, the hold before its first byte, and the `ObservedFailure` for its log entry), or `None` for an auxiliary request, a conversation without a script, or a script none of whose turns has started. Only a reply advances the script; a request posted again gets the same reply, and a failure answers without advancing it. A result check runs once, against the first request that carries the result. Two scripts for one conversation, or two turns pinned to one request, panic at registration. |
| `failure` | What a turn answers with in place of its content and the record of it, exported at the crate root: `StatusFailure` (`new(u16)`, `.with_count`, `.with_retry_after`, `.with_body`; an HTTP refusal, not a model declining to answer), `StreamError` (`new()` or `Default`, `.with_count`, `.with_message`, `.with_position(ErrorPosition::{First, Midway})`, `StreamError::DEFAULT_MESSAGE`), the texts `CUT_REPLY` and `LOOPING_REPLY`, the loop detector's `DOOM_LOOP_CHECK_HEADER` and `DOOM_LOOP_TRIGGER`, and `ObservedFailure` on a request's `LogEntry`: `Status(u16)`, `Stalled`, `Dropped`, `Cut`, `StreamError`, `DoomLoop`, and `None` for a plain answer; a stall combined with another failure records that failure. |
| `model_reply` | The crate private `ModelReply` is what a scripted conversation answers with before any endpoint format: `ToolCall { call_id, call }`, `Text(text)`, and the failure answers `LoopingReply { reported }`, `Refusal(StatusFailure)`, `StreamError(StreamError)`, `CutReply`, and `Dropped`. `into_response(endpoint, model)` renders a call and text as the `SseEvent`s of a `ScriptedResponse::sse`, using the `tool_call_turn` builders for a call and the byte exact `sse` builders for text, a failure stream as the failure shapes in `tool_call_turn`, a refusal as the status, `Retry-After`, and body the `StatusFailure` names, and a drop as the dropped body. |
| `tool_call_turn` | Crate private builders for one tool call turn with no reasoning and no text in each endpoint's format, each taking a `ToolCallTurn { call_id, name, arguments, model }`: `chat_completion_tool_call_events`, `responses_api_tool_call_events`, and `messages_api_tool_use_events`. ## Scripting the model

`set_conversations(conversations)` takes any iterator of `Conversation` and replaces the scripts. A replaced script that was not served through stays reported. `script_violations()` lists every `ScriptViolation` so far, and `assert_no_script_violations()` panics with them, the conversations opened, and the request log. Dropping the server runs the same check, so a scripted test cannot pass without its scripts having run. A test that expects a violation calls `finish_scripts()`, which stops serving the scripts and returns the violations so the drop check has nothing left. A test that returns `Result` must not let an early `?` drop the server before its scripts finish, since the panic replaces the error.

Conversation numbers follow arrival. The parent is `Conversation::nth(1)`, and two subagents started in one turn take 2 and 3 in either order, so script each with `for_system_prompt` of its prompt. Read a conversation back with `conversation(n)`, `conversation_for_system_prompt(contains)`, or `conversations()`; each carries its requests and the readers the `conversation` row lists.

A turn can also stall, refuse, cut, fail its stream, loop, or drop the connection with the failure setters listed in the `conversation_script` row, and pin itself to a numbered request with `.at_request(nth)`. A failure answers without advancing the script, so the client's retry meets the same position, and the mock records what it did on the request's `LogEntry` as `observed_failure`, so a test can assert the retry sequence.

## Examples

Script the model per conversation:

```rust
server.set_conversations(vec![
    Conversation::nth(1)
        .calls([
            MockToolCall::new(Tool::Read, json!({ "target_file": "a.rs" }))
                .result_contains("fn main"),
```

## Sandbox contract

- Keep the `TestSandbox` alive at least as long as every child using its paths.
- Use the builder only for construction time endpoint and git choices. Use `set_env` and `extend_env` for test specific flags, where the last override wins, and `remove_env` to test absence.
- Do not add process global env mutation. Keep filesystem and environment ownership in `TestSandbox`; process groups, output tails, and kill tree ownership stay in `TestProcess` and `TestProcessTree`.
- Diagnostics may name sandbox paths and sanitized loopback URLs. URL parsing fails closed: userinfo, query, and fragment are stripped, and malformed or non loopback values are redacted.

## Adding a capability

- **A response mode** (`inference_route.rs`): extend the private `ResponseMode` and its `text`, add the setter on `InferenceRoute` and its `MockInferenceServer` wrapper, and add the mode's arm per endpoint to the one `match` in `InferenceRoute::serve`. Scripted responses must still win. The echo pinning test must pass unmodified.
- **A wire format** (`sse.rs`): add the echo style builder and, if clients reconstruct text byte for byte, an `_exact` variant on a delta fn. Then add the endpoint to `InferenceEndpoint`, its arms to the `InferenceRoute::serve` match, its tool call builder in `tool_call_turn.rs`, its arm in `ModelReply::into_response`, and a route in `mock_server` if it is new. Keep the byte exactness pins green.
- **An expectation matcher** (`inference_override.rs`): keep the public matcher typed and narrow. Claim under the single expectation mutex before serving, replay only overlapping active duplicates by `RepostIdentity`, and add tests for auxiliary non consumption, concurrent one claim behavior, lifecycle barriers, and unsatisfied diagnostics. Expectations must stay ahead of required auth and fallback modes.
- **A scripted body kind** (`scripted.rs`): add the `ScriptedBody` variant, its render arm in `into_response_paced`, and eager checks in `validate`. Add a test asserting client visible bytes and keep the precedence over required auth green.
- **A tool** (`tools.rs`): add the `Tool` variant and its arm in `Tool::row`, giving it a GrokBuild name and any required field fills or shape. Then list it in the `tools` row above.
- **A turn capability**: add the field to the crate private `ScriptEntry` and the chainable builder method on `Conversation` or `MockToolCall`. `ReplayingScript::serve` answers a request in five steps: `run_pending_check`, `admit` (count the request and switch to a turn pinned there), `next_step` (the reply already taken, the turn's first failure with budget left, else its content), `record` (advance the script and charge a failure to its budget), and rendering as a `ModelReply` with the turn's hold and the `ObservedFailure` for the log. Put a new check beside `run_pending_check`, a new outcome as a `NextStep` variant, a new failure as a `Failure` variant in `failure.rs` answered in `failure_step`, and a new reply kind as a `ModelReply` variant rendered in `ModelReply::into_response` with its shapes in `tool_call_turn.rs`. Add one `respond` test and update the README rows.
- **A loopback double** (`mock_otel_server.rs` and `mock_managed_config.rs` are the two examples): build an axum `Router`, add `refuse_unserved`, and hand it to `LoopbackServer::serve`. Keep the state as `BoundedLog`s inside one `Watched<T>`, so every write is an `update` that wakes the waiters, readers are `read` snapshots, and a `wait_for_*` matches `wait_until`'s `WaitOutcome` into the double's own typed error. When the log is worth reading without the transport, keep it in a type of its own (`OtelRecorder`). A caller supplied reply (`ManagedConfigReply::Scripted`) is the escape hatch for what the double does not model.
