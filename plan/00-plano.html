Plano

Usar /sam-plan para verificar todo o repositório e planejar o uso do Jev (TypeSafe) sempre que possível no jev-build, com o Jev delegando à LLM o que não puder fazer.

Status

Status: NOT_CONFIDENT | Depth: standard | Case: FEATURE | Risk flags: security_privacy, auth_boundary, material_uncertainty | Council: required (ESCALATE_TO_FULL) | Residuals: Conselho full e artefatos do conselho pendentes (S-000); Chave/plano Jev não verificados (U-001); Números de valor, latência e calibração só existem após S-001/S-004; Backlog de seams deliberadamente fora da v1; Gap do bridge de telemetria do conselho

Goal & scope

Fazer o harness usar Jev para decisões estreitas e estruturadas sempre que a regra de elegibilidade permitir, começando pelo classificador de permissão do auto-mode, com autoridade Jev <= incumbent, fallback LLM intacto, flag default OFF, gate de avaliação medido e economia medida.

No-goimplementar sem o gate C • ligar por default • enviar conteúdo de arquivo/saída de tool sem opt-in • reapontar endpoint/enabled por config de projeto • retry/backoff no caminho quente

Thesis

Fundação reutilizável (cliente, config, flag, catálogo de perguntas, telemetria) -> instrumentar incumbent -> gate C1/C2 -> integração D1 em 2 fases -> medição/docs.

  • Rejected: hooks HTTP existentes (não podem conceder allow, logo não capturam o custo)
  • Rejected: crate novo distill-jev (exige editar o manifesto raiz gerado e sincronizado)
  • Rejected: Jev como gate autoritativo de allow (rev.1, rejeitado pelo conselho)
  • Rejected: converter 5-6 seams de uma vez (escopo especulativo)
  • Rejected: retry/backoff no caminho quente (autodestrutivo)
  • Rejected: tabela de preços local (custo é reportado pelo servidor)
  • Rejected: substituir sumário de compaction (geração é fora de escopo do Jev)
